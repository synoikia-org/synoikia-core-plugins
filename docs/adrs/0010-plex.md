# Plex Media Server

## Context and Problem Statement

Plex Media Server (PMS) serves a household's libraries. It serves no API spec, and Plex's own docs are incomplete. The community spec `LukeHagar/plex-api-spec` also describes plex.tv: accounts, sign-in, sharing and home users. Plex takes almost each argument in the query, and fetches URLs that a call gives it. Where does the catalog come from, which operations need a typed confirmation, and how does the plugin keep tokens hidden?

## Decision Drivers

- A third-party spec must not change the catalog without a plugin release.
- plex.tv account and sharing operations are out of scope.
- A whole library, server settings and DVR admin affect each user of the server.
- Plex fetches a URL for subtitles, extras, artwork and providers, and URLs can carry tokens.

## Considered Options

- The community spec at a pinned commit and SHA-256, PMS operations only. Lock library-wide, server-wide, admin and URL-fetching writes.
- Plex's own docs.
- The spec from its main branch.

## Decision Outcome

Chosen option: "The community spec at a pinned commit and SHA-256, PMS operations only". A change in the third-party repository or a mirror cannot change the catalog without a plugin release.

**Catalog source.**

1. `GET /` gives the server version. It needs the token, so it also proves the token.
2. `src/spec.ts` fetches `<specBaseUrl>/<ref>/plex-api-spec.yaml`. `ref` is a full commit SHA pinned in `plugin.yaml`, next to the file's `sha256`.
3. `parseSpecSource` refuses a branch or tag name. `fetchPlexSpec` refuses a file whose SHA-256 differs, from GitHub or a mirror.
4. `specBaseUrl` defaults to `https://raw.githubusercontent.com/LukeHagar/plex-api-spec`. No credentials go there. Both hosts are in `network.hosts`.

- **PMS only.** `pmsOnly` drops each operation that declares its own `servers`, which are the plex.tv and cloud operations. No plex.tv host is in `network.hosts`.
- **`:` paths.** Plex keeps actions under a `:` segment, such as `/:/prefs`. The SDK's OpenAPI adapter skips these, so `src/catalog.ts` builds them under a placeholder and restores them. A spec that already uses the placeholder is refused.
- A spec with fewer than 250 PMS operations is refused. So is one that misses a key that `plugin.yaml` locks, splits or makes a write by name (`requiredKeys` in `src/locks.ts`). A key that moves to plex.tv counts as missing.

**Requests.** Each request sends `X-Plex-Token`, `Accept: application/json`, a stable `X-Plex-Client-Identifier` and `X-Plex-Product: Synoikia`. `src/request.ts` runs on each call, before the split checks.

- A query with two keys that differ only in case is refused (`INVALID_PARAMS`).
- The keys in `plugin.canonicalKeys` are renamed to Plex's spelling. Each takes one plain value. A list or an object is refused, because Plex would read a value that the target or split did not check.
- `X-Plex-Token` in the query is refused, because the plugin authenticates.
- A query or body that holds `[REDACTED]` is refused.

**Classification.** GET reads, every other verb writes, and anything unsettled is a write.

Regular writes, by review: one item's metadata, match or detection, library scans, collection and hub order, and Continue Watching. Also update checks, one maintenance task, stopping one playback, single-item deletes and DVR create. Each is reversible or acts on one item, and its target names it. The owner decided that section index and intro deletes, and media provider deletes, are regular writes.

**Targets.** Writes name the library section, up to 10 items, the playlist and the session (`user playing title on player`). They also name the settings that `PUT /:/prefs` changes, and the origin of a `url` that Plex fetches. Model strings are escaped.

**Secrets.**

- `sensitiveKeys`: `token`, `X-Plex-Token`, `authToken`, `accessToken`, `authenticationToken`, `PlexOnlineToken`, `password`, `secret`.
- `src/mask.ts` masks a token in a URL query anywhere in a result. It also masks the `value` of a server setting whose `id` names a secret, such as `PlexOnlineToken` or `customCertificateKey`.
- `sensitiveParams: [/query/url]` on each operation, and `/query/uri` on `POST /media/grabbers/devices`. The approval and the audit log show only the URL's origin, as a target.

### Consequences

- Good, because the catalog changes only with a plugin release.
- Good, because each URL that Plex fetches needs a human, and the approval names its origin.
- Bad, because plex.tv sharing, friends and home users are out of scope.
- Bad, because the plugin depends on a community spec, and a new Plex feature waits for it.

The feature file in `features/plex/` and `plugins/plex/test/compliance.yaml` specify the behavior.
